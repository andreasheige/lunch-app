# lunch-app

Shows today's lunch menus for restaurants around Platinan by Centralen in Göteborg (where the Knowit office is). Strict TypeScript (TS 7), run directly by Node ≥22.18 (type stripping) and wrangler. One runtime dependency: SortableJS (the "Sortera" drag and drop; `astro.config.mjs` copies its minified file to `dist/vendor/`, loaded only in sort mode). Pages are built by Astro (static output, dev dependency only).

- `src/shared/types.ts` — shapes shared by server and client (`LunchResponse`, `Dish`, `ReportRequest`, …)
- `src/server/restaurants.ts` — restaurant list + one parser per site (page text lines → today's dishes)
- `src/server/pdf.ts` — dependency-free PDF text extraction (Canva exports; drops rotated background text) for PDF menus (`pdf` field on a restaurant)
- `src/server/diet.ts` — veg/fish/meat per dish: from the restaurant's category label, else guessed by Workers AI (Llama 3.3 70B via the Worker's `AI` binding; answer edge-cached a day per dish list, free tier), plus a dish-kind icon (🍔 🍲 🍛 …, by keyword on the dish name) and allergens the menu text mentions (keyword lists; never free-from claims)
- `src/server/translate.ts` + `public/i18n.js` — English mode (SV/EN toggle in the nav, localStorage `lunch-lang`, default EN unless the browser prefers Swedish; switching reloads). UI text lives in `i18n.js` (`t()`, `data-i18n` attributes). Menu texts are translated by Workers AI at `/translations.json` (sv → en map, answer edge-cached a day); `lunch.json` itself stays Swedish because ratings and the picker key on it. `/stats.json` and `/releases.json` take `?lang=en` (English notes in D1 `release_notes_en`)
- `src/server/lunch.ts` — fetches pages, picks today's weekday (Europe/Stockholm), caches 30 min
- `src/server/worker.ts` — Cloudflare Worker (`wrangler.jsonc`): live `/lunch.json` edge-cached 30 min (keyed by deployed version, so deploys need no purge), rest from `dist/`
- `src/server/report.ts` — `POST /report`: in-page form → GitHub issue (honeypot, Turnstile, per-IP rate limit); Worker secrets `TURNSTILE_SECRET`, `GITHUB_TOKEN`
- `public/picker.js` — "Välj åt mig": 3 random questions from a pool score dishes/restaurants (plus distance, open now, the diet filter and the per-browser visit history in localStorage); pure functions, tested in `test/picker.test.js`
- `src/server/releases.ts` + `src/site/pages/news.astro`, `news/[slug].astro` — a changelog at `/news`, one post per release at `/news/<slug>`: the build groups feat/fix commits from git log by the PR they came from (`gh api graphql`; in CI `GH_TOKEN`, without it each commit is its own release) into `dist/releases-source.json`; the Worker's `/releases.json?lang=sv|en` has Workers AI write each release up once per language (title, summary, intro, changes as new/improved/fixed; 4 per request) and keeps it in D1 `release_posts`. The pages carry the Swedish posts the live site had written at build time (`src/site/news.ts`, `.astro/news-snapshot.json`); `public/news.js` filters by label and redraws from `/releases.json` in English or while a post is pending. `sitemap.xml` is generated (`pages/sitemap.xml.ts`) and lists every post
- `src/server/ratings.ts` + `src/site/pages/stats.astro` — 1–5 stars per dish on today's menu (`POST /rate`, only dishes on today's menu — or, with `date`, on the previous lunch day's served menu in `menu_days`, rated from the "Betygsätt gårdagens lunch" section under the listing that `/yesterday.json` fills (open on weekends) — random per-browser voter id, no IPs/names; `RATE_LIMITER`), today's averages at `/ratings.json`, and `/stats.json?range=14|all` for `/stats`: six tabs in `public/stats.js` (Overview: league + plate wall; Analytics: charts + sortable table; Dashboard, Graph (ingredient network) and Visuals from today's menu plus D1 `menu_days`; History from `/history.json`); the calculations live in `public/statsdata.js` (tested in `test/statsdata.test.js`); diet and star colours are CSS variables in `stats.css`, validated with the dataviz validator
- `src/server/menudays.ts` — each `/lunch.json` miss stores today's served dishes in D1 `menu_days` (date, restaurant, dish, diet, allergen mentions) so the stats can compare days
- `src/server/history.ts` — menu history from `menu_days`: each `/lunch.json` miss marks dishes the place served on earlier days (`served: {times, last}`, a line in the opened dish); `/history.json?lang=` has the latest week's menus, its best-rated dishes and the dishes that come back (`recurringDishes`: served again after a menu day without them, and on at most 60% of the place's days, so fixed menus and weekly specials don't count). Shown as the weekend recap on the home page (weekends have no listing, only the notice and the recap) and the "Historik" tab on `/stats` (`/stats#history` opens it)
- `public/manifest.webmanifest` + `icon-192/512.png`, `apple-touch-icon.png` — installable to the home screen (standalone). The footer link "Lägg till på hemskärmen" (`setupInstall` in `app.js`) opens Chrome's/Android's own install prompt (`beforeinstallprompt`); on iOS, which has no prompt, it shows the Share → Lägg till på hemskärmen steps. Hidden on desktop and when already installed
- `src/server/notify.ts` — reporters can tick "mejla mig" in the report form: name/email go to D1 `report_contacts` (never GitHub); a 15-min cron (`scheduled` in worker.ts) checks their issues and, once closed, emails them from hej@lunchit.se (Cloudflare Email Sending, `EMAIL` binding) and deletes the row (or after 180 days). Test locally: `wrangler dev --test-scheduled`, then `curl 'localhost:8787/__scheduled'`
- `migrations/` — D1 (`lunch-app`, binding `DB`) schema; apply with `npx wrangler d1 migrations apply lunch-app --remote` (and `--local` for `wrangler dev`)
- Look: "Lunchbox" — warm cream / herb green, Bricolage Grotesque (headings, bold) + DM Sans (text), self-hosted from `public/fonts/` (SIL OFL). Tokens in `src/site/styles/site.css` (stats/news styles in `stats.css`/`news.css`, so each page inlines only its own); light by default, warm dark from the system or the header's sun/moon toggle (`public/theme.js`, localStorage `lunch-theme`, applied before first paint by an inline script in `Layout.astro`)
- Home controls: a "Kan du inte bestämma dig?" card opens the picker; diet chips (Alla/Veg/Fisk/Kött) filter at once, the Allergener chip opens a sheet; "Visning" (a popover) holds the view and order choice
- `public/app.js` listing — three views of the same menus, switched with "Kort · Lista · Rätter" (remembered in localStorage `lunch-view`): cards (phone default; dishes are `<details>` that open to description and rating), overview (wide-screen default: a row per place, the chosen place's menu beside it; an accordion on phones) and dishes (a table on wide screens). `renderListing()` redraws the current view; the filter is applied at render time. "Sortera" puts the places in your own order (drag handles + move buttons, localStorage `lunch-order`); places whose lunch is over still go last
- `src/site/` — Astro pages (`pages/index|stats|news.astro`) and the shared `components/Layout.astro` (head + nav); `astro.config.mjs` writes them to `dist/` as `stats.html` etc. (the old Swedish URLs `/statistik` and `/nyheter` 301 via `public/_redirects`) Client JS stays plain files in `public/`, copied as is and loaded with `is:inline` (not bundled), so tests import them directly; the stylesheet `styles/site.css` is inlined into each page
- `server.ts` — local dev: serves the built `dist/` and a live `GET /lunch.json`; the D1/Workers AI endpoints (`/ratings.json`, `/stats.json`, `/history.json`, `/yesterday.json`, `/translations.json`) answer empty and `POST /rate` 503s — real ratings, stats and history need `npm run dev`
- `scripts/capture.ts` — reads Poppels' Canva menu text with a headed Playwright Chromium (headless is blocked by Cloudflare) into `captured.json`; CI runs it under `xvfb-run` before the build
- `scripts/build.ts` — the site build (`npm run build`): fetches today's menus, runs `astro build` with them as `LUNCH_SNAPSHOT` (so the home page's HTML carries the menus and JSON-LD for crawlers, agents and no-JS readers; `src/site/snapshot.ts`, `components/Place.astro` mirrors the cards view in `app.js`), then adds the `lunch.json` snapshot, `releases-source.json` and `captured.json` (which the Worker reads via `ASSETS`) to `dist/`
- `public/robots.txt`, `llms.txt` (+ the generated `sitemap.xml`) — for crawlers and agents; `llms.txt` describes the JSON endpoints
- `.github/workflows/deploy.yml` — tests, captures, builds and `wrangler deploy`s to Cloudflare on push to main and weekdays 08:00 UTC
- `test/fixtures/*.txt` — each parsed site's page flattened with `htmlToLines`, captured 2026-09-28 (v. 40); `delissimo.pdf` is the raw menu PDF; `poppels.txt` is `scripts/capture.ts` output from 2026-10-06 (v. 41); `carotte.txt` and `bbbangers.txt` are from 2026-10-06 (v. 41); `bjorkmans.html` is the raw page (scripts/styles stripped) from 2026-10-17 (v. 42) — Björkmans parses Wix rich-text blocks, not lines

## Common commands
- `npm run dev` — the real Worker with a local D1 on http://localhost:8787: full build, `wrangler d1 migrations apply --local`, `wrangler dev` (wrangler is a pinned dev dependency). Ratings, stats, history and "rate yesterday" only work here; the local D1 starts empty and fills from weekday `/lunch.json` requests and your votes
- `npm start` — `astro build`, then run on http://localhost:3000 (`PORT=…` to change); after editing pages or `public/`, `npx astro build` again (the server reads `dist/` per request). The D1 endpoints answer empty here
- `node scripts/capture.ts` — capture Poppels locally (opens a Chrome window; `npx playwright install chromium` once)
- `npm run build` — build `dist/` with today's menus in the HTML (prints one line per restaurant)
- `node --test --test-reporter=dot` — quiet test run
- `npm run -s lint` — Biome lint + format check (`npm run format` applies fixes)
- `npm run -s typecheck` — tsc (TS 7) over the node, worker, test and client tsconfigs

Port 3000 is often taken on this machine; use e.g. `PORT=3124 npm start`.

Lighthouse (13.5, incl. the agentic-browsing category): every page scored 100 in all categories, mobile and desktop, on 2026-10-13. Measure against `npm run dev` (the real Worker and asset handling), not `npm start`. Keep it there: menus are in the built HTML, the stylesheet is inline, the home page stays under ~14 kB gzipped (one network round trip; JSON-LD carries dish names only), app.js fetches the live data only after the first paint, space is reserved for what app.js fills in (no layout shift), and third-party embeds (Canva) load only on request.

When a site changes layout, re-capture its fixture with `htmlToLines` and fix that site's parser.
